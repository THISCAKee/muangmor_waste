# ตั้งค่าระบบจริง

ระบบอ่านข้อมูลจาก Google Sheets (แท็บ `payment_DATA` และ `slip`) ผ่านเซิร์ฟเวอร์ เมื่อประชาชนส่งสลิป ระบบจะบันทึกรูปลงโฟลเดอร์ Drive และเพิ่มแถวในแท็บ `slip` จากนั้นเจ้าหน้าที่ตรวจใน AppSheet ตามเดิม (ใส่ ✅ ในคอลัมน์สถานะ)

## 1. ทดสอบกับสำเนาชีตก่อน

ห้ามทดสอบการเขียนข้อมูลกับชีตจริง ให้ทำสำเนาก่อน (ไฟล์ → ทำสำเนา) แล้วใส่ ID ของสำเนาใน `SHEET_ID` เมื่อทดสอบผ่านแล้วจึงเปลี่ยนกลับเป็น ID ของชีตจริง

## 2. สิทธิ์เข้าถึง Google (เลือก 1 แบบ)

**แบบ A — Service Account** (ใช้ได้เมื่อมี Google Workspace และ Shared Drive)

1. Google Cloud Console → สร้างโปรเจกต์ → เปิดใช้ Google Sheets API และ Google Drive API
2. IAM → Service Accounts → สร้างบัญชี → Keys → Add key → JSON
3. แชร์ชีตให้อีเมลของ Service Account เป็น "ผู้แก้ไข"
4. สร้างโฟลเดอร์สลิปใน **Shared Drive** แล้วเพิ่ม Service Account เป็นสมาชิก (Service Account อัปโหลดลง Drive ส่วนตัวของ Gmail ไม่ได้ เพราะไม่มีพื้นที่เก็บไฟล์ของตัวเอง)
5. ใส่ไฟล์ JSON ทั้งก้อนเป็นบรรทัดเดียวใน `GOOGLE_SERVICE_ACCOUNT_JSON`

**แบบ B — OAuth ในนามเจ้าของชีต** (ใช้กับบัญชี Gmail ทั่วไป)

1. Google Cloud Console → เปิดใช้ Sheets API และ Drive API
2. OAuth consent screen → External → กด **Publish app** ให้เป็นสถานะ In production (ถ้าค้างไว้ที่ Testing โทเคนจะหมดอายุทุก 7 วัน)
3. Credentials → Create OAuth client ID → ชนิด **Desktop app**
4. รัน `GOOGLE_OAUTH_CLIENT_ID=... GOOGLE_OAUTH_CLIENT_SECRET=... node scripts/google-oauth.mjs` แล้วล็อกอินด้วยบัญชีที่เป็นเจ้าของชีต
5. นำค่าที่ได้ใส่ใน `GOOGLE_OAUTH_REFRESH_TOKEN`

## 3. ค่าอื่นๆ

ดูรายการทั้งหมดได้ใน `.env.example`

- `DRIVE_FOLDER_ID` — โฟลเดอร์เก็บรูปสลิป
- `ORDER_SECRET` — สร้างด้วย `openssl rand -hex 32`
- `BILLER_TAX_ID`, `BILLER_SUFFIX`, `KTB_COMP_CODE` — Bill Payment กรุงไทย (บาร์โค้ด/QR ที่มี Ref1/Ref2) ถ้าตั้งไว้ จะใช้แทน QR พร้อมเพย์ ดูรายละเอียดใน [KTB-BILL-PAYMENT.md](KTB-BILL-PAYMENT.md)
- `PROMPTPAY_ID` — เลขผู้เสียภาษี 13 หลักของเทศบาล (หรือเบอร์พร้อมเพย์) ต้องตรวจกับกองคลังก่อนเปิดใช้
- `PAYEE_NAME` — ชื่อบัญชีที่แสดงใต้ QR

ตอนพัฒนาในเครื่อง ให้คัดลอก `.env.example` เป็น `.env.local` แล้วรัน `npm run dev`

## 4. ชำระผ่านแอปธนาคาร (เลือกธนาคาร → เด้งเข้าแอป)

ลำดับการทำงาน: ประชาชนเลือกเดือน ระบบล็อกยอด → เลือกธนาคาร → แอปธนาคารเปิดขึ้นมาพร้อมยอดและบัญชีเทศบาล → กดยืนยันโอน → กลับมาที่เว็บ ระบบยืนยันกับ Gateway แล้วเพิ่มแถวในแท็บ `slip` เป็นสถานะ `✅ชำระออนไลน์` ประชาชนไม่ต้องส่งสลิป

ต้องมีบัญชีร้านค้ากับ Payment Gateway เพราะธนาคารไม่เปิดให้เว็บทั่วไปส่งยอดเข้าแอปได้เอง ระบบนี้เขียนไว้สำหรับ **Opn Payments (Omise)** ซึ่งรองรับ K PLUS, SCB EASY, Krungthai NEXT, Bualuang mBanking และ KMA

1. สมัครบัญชีร้านค้าที่ opn.ooo ในนามเทศบาล และเปิดใช้ช่องทาง Mobile Banking (ต้องสอบถามเรื่องค่าธรรมเนียมและเอกสารสำหรับหน่วยงานรัฐ)
2. ใส่ `PAYMENT_PROVIDER=opn` และ `OPN_SECRET_KEY` (ทดสอบด้วยคีย์ `skey_test_...` ก่อน)
3. Dashboard ของ Opn → Webhooks → ใส่ `https://<โดเมน>/api/payments/webhook` เพื่อให้บันทึกได้แม้ประชาชนไม่ได้กลับมาที่เว็บ
4. ตั้ง `PUBLIC_URL` เป็นโดเมนจริง

ระหว่างรอบัญชีร้านค้า ใช้ `PAYMENT_PROVIDER=mock` กับ `npm run dev` เพื่อสาธิตขั้นตอนได้ (หน้าธนาคารจำลอง ไม่มีการตัดเงินจริง)

ถ้าไม่ตั้ง `PAYMENT_PROVIDER` หน้าเว็บจะแสดงเฉพาะ QR พร้อมเพย์และช่องส่งสลิป

## 5. Deploy บน Vercel

1. Push โค้ดขึ้น GitHub แล้ว Import โปรเจกต์ใน Vercel
2. Settings → Environment Variables → ใส่ค่าทั้งหมดจากข้อ 2–4
3. Deploy

## 6. หลังเปิดใช้งานจริง

- **ปิดการแชร์ลิงก์สาธารณะของชีต** (แชร์ → การเข้าถึงทั่วไป → จำกัด) ตอนนี้ใครที่มีลิงก์ก็เปิดดูชื่อ ที่อยู่ เบอร์โทร และอีเมลเจ้าหน้าที่ได้ ระบบใหม่อ่านผ่านสิทธิ์ของข้อ 2 จึงไม่ต้องเปิดสาธารณะ (เว็บเดิมที่อ่านผ่าน gviz จะใช้งานไม่ได้หลังปิดแชร์ ให้ปิดพร้อมกับตอนย้ายไปเว็บใหม่)
- ทดลองส่งสลิปหนึ่งรายการ แล้วตรวจใน AppSheet ว่าแถวใหม่แสดงครบ และรูปเปิดได้

## ข้อจำกัดที่ควรรู้

- แท็บ `slip` ผูกกับผู้ชำระด้วย**ชื่อ**เท่านั้น ถ้าเพิ่มคอลัมน์ `keyลูกค้า` และ `เลขอ้างอิง` ท้ายแท็บ `slip` (แล้วกด Regenerate structure ใน AppSheet) ระบบจะบันทึกค่าเหล่านี้ให้อัตโนมัติ และแยกคนชื่อซ้ำได้ถูกต้อง
- คอลัมน์ `status_sent` เว้นว่างไว้ ถ้า AppSheet ใช้คอลัมน์นี้ส่งแจ้งเตือน ให้ตรวจว่าแถวใหม่ทำงานตามที่ต้องการ
- การชำระด้วย QR พร้อมเพย์ไม่มีการยืนยันจากธนาคาร เจ้าหน้าที่ยังต้องตรวจสลิป ส่วนการชำระผ่านแอปธนาคาร (ข้อ 4) Gateway จะยืนยันให้เอง
- แถว `✅ชำระออนไลน์` ยังไม่ได้ออกใบเสร็จหรือกรอกยอดลงคอลัมน์รายเดือนใน `payment_DATA` เจ้าหน้าที่ยังต้องทำขั้นนี้ใน AppSheet ตามเดิม
